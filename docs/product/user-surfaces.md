# User Surfaces

## Student Dashboard

The student dashboard is a responsive desktop-first terminal-style interface. The protected `/dashboard` route is guarded by a Supabase session plus trusted `app_role=student` claim check and now renders current-turn gameplay data through the safe dashboard executor, using a Supabase-backed row reader when the App Router server client is available and bounded rows only as the local fallback, plus a bounded browser TARA order form, a first post-turn attribution panel from existing safe student envelopes, and a first Realtime refresh subscription status panel with parse-first refresh-only payload handling plus route-scoped authorized server query result status. It must remain free of future macro rows, other-student exact holdings, raw ledger drafts, order details, provider payloads, and instructor God Mode data.

Required surfaces:

- Macro news terminal.
- Current macro, market-string, and scenario-driver metrics.
- Pyramid/funnel portfolio visualizer.
- TARA order entry.
- Estimated tax drag preview.
- Post-turn attribution report.
- Leaderboard rank view.

The MVP pure-domain student dashboard current-turn snapshot composes the safe current macro news, Driver/String metrics, portfolio pyramid, TARA order-entry, and leaderboard-rank section payloads for one already-scoped viewer fund before UI, server queries, authorization enforcement, persistence, or database code exists.

The MVP student dashboard current-turn query descriptor records the server-query boundary for one already-scoped class, current month, and viewer fund. The current-turn dashboard query result envelope wraps an already-authorized current-turn dashboard snapshot for that descriptor only when class, current-month, and viewer-fund scope match, without returning database rows, provider clients, future scenario rows, other-fund exact holdings, instructor God Mode data, ledger drafts, or provider payloads. The current-turn dashboard query result validation failure envelope maps missing or mismatched query results to student-safe validation errors without returning snapshots, database rows, provider clients, UI state, other-fund exact holdings, instructor God Mode data, future scenario rows, ledger drafts, or executed query metadata. The first Supabase-backed row reader now loads scoped current-turn provider rows behind the existing parser/executor when server Supabase auth is configured, including a class-membership-gated student leaderboard RPC that returns only leaderboard-safe fund fields; hosted execution proof remains pending.

The MVP pure-domain student post-turn dashboard snapshot composes the viewer fund attribution report and leaderboard-rank section payloads for one already-scoped viewer fund and processed class month before persistence or database code exists. The MVP pure-domain student post-turn dashboard query descriptor records the future server-query boundary for that processed class month and viewer fund without executing server queries, auth/session checks, RLS, database access, provider clients, result delivery, or attribution payload delivery. The MVP pure-domain student post-turn dashboard query result envelope wraps an already-authorized post-turn dashboard snapshot only when class, processed-month, and viewer-fund scope match, without executing server queries, auth/session checks, RLS, database access, provider clients, result delivery, or attribution payload delivery. The protected student dashboard now renders a first bounded post-turn attribution panel from that safe snapshot/query-result envelope with empty, safe failure, and success states while still excluding target weights, order details, raw ledger drafts, other-fund ledger rows, provider payloads, future scenario rows, class aggregate payloads, and instructor God Mode data. ## Realtime Refresh

After the engine completes monthly processing, connected student screens must refresh to the new month without requiring manual reload.

The MVP pure-domain turn-completion event carries only class-level processing metadata and aggregate totals for the future refresh signal; exact per-fund ledger drafts stay out of the class-level realtime payload. The first bounded Inngest class-month processing executor can return that aggregate event plus a safe persistence receipt after injected processing, while hosted worker execution, live ledger writes, processed-order mutation, and realtime publication remain unwired.

The MVP pure-domain refresh signal derived from that event carries only class/month refresh metadata and dedupe keys so future clients refetch authorized current-month surfaces instead of receiving gameplay data directly through the refresh trigger.

The MVP pure-domain publication envelope wraps that refresh signal with provider-neutral class-channel, event, audience, and refresh-only delivery metadata before provider-specific Supabase Realtime publication, subscriptions, auth, or client refetch code exists.

The MVP pure-domain Supabase Realtime publication descriptor maps the provider-neutral envelope into a typed broadcast boundary contract while preserving refresh-only payload semantics before hosted provider clients, subscriptions, auth, or client refetch code exists. The first infrastructure publisher now consumes that descriptor through an injected server-only client shape, sends only the typed refresh broadcast message, and returns safe result/failure envelopes without gameplay payloads, query results, provider clients, provider errors, or secrets.

The MVP pure-domain Supabase Realtime subscription descriptor maps that broadcast descriptor into a client subscription boundary contract that instructs clients to refetch authorized current-turn surfaces without carrying gameplay data in the realtime payload. The protected student and instructor dashboards now render a first browser-visible subscription/refetch status panel using that descriptor chain, with safe public-env fallback when Supabase browser configuration is missing.

The MVP pure-domain realtime authorized current-turn refetch descriptor maps that subscription descriptor into a client refetch plan for authorized student and instructor current-turn surfaces without carrying gameplay data in the realtime payload. The browser panel validates unknown broadcast payloads against the refetch plan and calls `router.refresh()` only after accepting a refresh-only, class/month/idempotency-matched payload.

The MVP pure-domain realtime authorized current-turn query descriptor maps that refetch plan into future server-scoped query instructions for the student and instructor current-turn dashboard surfaces without executing server queries, auth/session checks, database access, UI refetches, or provider subscriptions.

The MVP pure-domain realtime authorized current-turn query result envelope wraps already-authorized student and instructor current-turn dashboard snapshots for those query instructions only when the snapshots match the refreshed class and current month, without returning database rows, provider clients, ledger drafts, fund processing keys, aggregate financial totals, or gameplay data through the realtime payload. The protected student and instructor realtime panels now display a route-scoped ready or validation-stopped server query result status for the current dashboard surface after server rendering, including renders triggered by accepted `router.refresh()` events. The MVP pure-domain realtime authorized current-turn query result validation failure envelope maps missing or mismatched already-authorized dashboard snapshots to server-query-result validation errors without returning snapshots, database rows, provider clients, ledger drafts, fund processing keys, aggregate financial totals, UI state, or provider execution details.

Future implementation should use Supabase Realtime or the accepted realtime provider in `docs/product/runtime-architecture.md`.
